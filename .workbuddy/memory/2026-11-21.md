## 修复「只能切一族方向，另一族转一下又弹回来」

### 症状
用户在界面卡片上点「横屏」：屏幕确实转到横屏 → 顶部显示「横屏未生效」→ 又弹回竖屏。
先前一版的现象是镜像的（只能切横屏，竖屏不行），说明与「哪一族」无关，而与「当前所处的那一族」有关。

### 根因（已用日志证实）
`MainActivity` 在清单里声明了 `android:screenOrientation="fullSensor"`。
Activity 的方向声明本身就是系统方向仲裁里的一个请求方，与 1×1 悬浮窗
（`WindowManager.LayoutParams.screenOrientation`）的请求并列；两者不一致时 HyperOS 会互相顶：
悬浮窗请求先被采纳 → 屏幕转过去 → 界面按自己的方向把显示拉回去 → 界面每次旋转都重建、
再参与一次仲裁 → 来回震荡，最终停在原方向并显示「未生效」。

证据：`logcat -b events` 里 `wm_on_stop_called ... handleRelaunchActivity`
在 22 秒内出现 11 次（每 0.7 秒重建一次），即屏幕在两族之间持续翻转。
`fullSensor` 更隐蔽的一层：它会按传感器解析出一个具体方向，所以表现为「手机怎么拿，就只有那个朝向能用」，
这也解释了前后两次报告为何是镜像的。

对照实验：把清单改成固定 `portrait` 后，由服务请求横屏，屏幕连转都不转 → 证明 Activity 的方向请求
可以直接压住悬浮窗。

### 修复
1. 清单不再给 Activity 声明 `screenOrientation`。
2. `MainActivity.syncRequestedOrientation()`：按 `RotationPrefs` 调 `setRequestedOrientation()`，
   AUTO 时设 `SCREEN_ORIENTATION_UNSPECIFIED`；在 `onResume`、`pick()` 之后、`onNewIntent` 之后调用。
   界面与悬浮窗两个请求方同向，系统不需要取舍。
3. 删除上一版的「方向自愈」（DisplayListener + 重推/拆窗重建 + 重试计数）：
   它追的是症状，拆窗重建本身会制造一次可见回弹，而且会去对抗「本来就该覆盖方向」的第三方应用。
   同时删掉 `OverlayController.reassert()` 和 `RotationMode.displayRotation`。

### 验证（Redmi 23049RAD8C / HyperOS，serial a766eaed）
- 真机点卡片竖屏↔横屏连续 3 轮：`ROTATION_0` / `ROTATION_90` 全部正确且稳定。
- 偏好注入四向往返：0 / 90 / 180 / 270 全部正确。
- 锁横屏后回桌面：launcher 保持 90，说明悬浮窗路径未被削弱。
- 装的是带修复的 debug APK；设备已恢复为「自动」。

### 调试踩坑（重要）
- 横屏布局下 adb `input tap` 的坐标空间是 2400x1080；屏幕方向在测试中途变化会让先前的 uiautomator
  bounds 失效，导致「点不中」并误判成「功能没生效」。结论：dump 与 tap 必须在同一次方向状态下完成。
- `android:exported="false"` 的前台服务无法用 `am start-foreground-service` 从 shell 拉起，
  会报 `Requires permission not exported`。要注入模式用 `am start --es extra_pending_mode <key>`
  （走 MainActivity），或先 force-stop、用 sed 改 `shared_prefs/rotation.xml` 再启动（走 ensureApplied）。

## 通知栏控制条改成「应用内一键开启」的标准流程

### 需求
主界面放一个开关，首次打开时（Android 13+）在当前页面之上弹系统原生「是否允许发送通知？」，
点允许 → 开关打开 + 控制条立刻出现。

### 实现
- 新增 `NotificationBarPrefs`（`enabled` 默认 false、`hasRequested` 记录是否问过权限）。
  **默认关闭**：开关的字面语义就是「通知栏里有没有那排按钮」，不做静态假象。
- `MainActivity.onNotificationBarToggled`：三道门 → 无悬浮窗权限（去设置、回弹）→ 无通知权限
  （`requestPermissions(POST_NOTIFICATIONS)`，系统原生弹窗盖在当前页上）→ 权限在但通知总开关关了
  / 已被系统判定不再询问（跳应用通知设置）。`onRequestPermissionsResult` 里授权成功直接
  `enableNotificationBar()`，拒绝则回弹开关。
- 开关显示条件 = 偏好 ∧ 通知可发（权限 + `areNotificationsEnabled`）∧ 有悬浮窗权限，副标题分
  「未开启 / 需要授权 / 已被系统关闭」三种文案（`EntryRowView.setSubtitle`）。
- `RotationService`：新增 `barEnabled` 作为服务常驻的第三个理由，因此**方向停在「自动」时也能只为
  控制条常驻**；`setNotificationBarEnabled()` 打开即 `startForeground`（`FOREGROUND_SERVICE_IMMEDIATE`），
  通知当场出现。关闭时若还有别的常驻理由，通知降级成纯文本、不再挂 RemoteViews。
- `setMode` / `setBallEnabled` 的 stopService 条件都要带上 `NotificationBarPrefs`，否则切「自动」会把
  用户要的控制条一起停掉。
- 移除原先「选方向 / 开悬浮球时顺手请求通知权限」的行为：权限只由这个开关触发，不再突然弹窗。

### 验证
- `gradle assembleDebug`（本机 gradle 8.14.3，离线）通过。
- 真机 a766eaed（Redmi 23049RAD8C / HyperOS，Android 15 / API 35）逐分支验证：
  1. 全新状态（`pm clear` + `appops set SYSTEM_ALERT_WINDOW allow`）点开关 → 原生弹窗
     「允许"屏幕旋转"发送通知？」盖在应用上 → 点「始终允许」→ 权限 granted、服务 isForeground、
     通知 contentView=notification_controls、**方向仍为「自动」**（证明 bar-only 常驻生效）。
  2. 下拉通知栏可见一排五个图标，点「横屏」→ `rotation.xml mode=landscape`、`ROTATION_90`。
  3. 关开关 → `enabled=false`，服务仍 isForeground（方向锁定），通知 `contentView=null`（降级成功）。
  4. 再开 → contentView 立刻恢复。
  5. 全新状态点开关 → 点「拒绝」→ 开关回弹 + Toast「未允许通知…」，`enabled=false`，服务数为 0。
  6. 拒绝后再点一次 → 系统仍会弹第二次（canAsk 判定正确，没有提前跳设置）。
  7. 只剩控制条时关掉 → 服务数 0、通知数 0，无残留。

### 踩坑
- `adb shell` 传 `/sdcard/xxx` 会被 Git Bash 当成本地路径改写，必须 `export MSYS_NO_PATHCONV=1`，
  否则 `uiautomator dump` 会写到 `Files/WorkBuddy/resources/vendor/PortableGit/sdcard/` 下。

## 悬浮球展开不再越出屏幕

### 症状
球贴在边缘时点开，面板先有一半在屏幕外，再用 190ms 滑进屏幕，观感很别扭。

### 修法（`FloatingBallController` + `FloatingBallView`）
1. `expand()` 不再「先摆到球心位置再动画位移」，而是**一步**把 200dp 窗口 clamp 进
   `[0, bounds-panel]`，删掉那段 `ValueAnimator` 位移。窗口本身始终整块在屏幕内。
2. 窗口被挪动后球会瞬移，因此 `FloatingBallView` 新增锚点 `anchorX/anchorY`
   （= 原球心 − 面板中心）：`onDraw` 里以 `contentX = cx + anchorX*(1-f)` 绘制中心球与四个方向键，
   展开完成时锚点自然归零。面板底色圆仍画在窗口中心（本来就是屏幕内的），
   所以动画全程没有任何像素跑出屏幕。
3. `collapse()` 收尾用 `面板中心 + anchor` 还原球的真实位置，然后把 anchor 归零再 update，
   避免下一次静止绘制被二次偏移。
4. 去掉位置滑动后，球不再因为反复展开而被推到 `panel/2` 高处（顺带修掉了漂移）。

### 验证（首版只编译，未上真机 → 上真机后发现问题，已一并修掉）
1. 真机 a766eaed（Redmi 23049RAD8C / HyperOS，1080x2400，density 440）实测：
   把 `animator_duration_scale` 调成 10 让 210ms 展开变成 2.1s，逐帧抓图量像素。
   - 展开 30%：面板底圆右边缘止于 x=1073（屏幕 1080），整块在内；中心球此时是蓝色
     「自动」按钮（f>0.3 会变蓝），仍停在球的原始位置附近。**注意：别再拿「深色块」当判据，
     那时中心球已经变蓝，检测会漏。**
   - 展开完成：面板 536x536、中心 (804,1154)、右余 7px。
   - 收起 50%：球在 (955,1154)，右余 53px；收起完成：球回到 (994,1154)。
2. **顺带发现并修复一个原有致命 bug**：`FloatingBallController` 里匿名对象的
   `override fun onSelect(mode) { collapse(); onSelect(mode) }` —— Kotlin 把 `onSelect(mode)`
   解析成这个匿名对象自己的方法，自己调自己 → `StackOverflowError`，进程崩溃、悬浮球消失。
   改为 `this@FloatingBallController.onSelect(mode)`。修前从悬浮球点任何方向必崩。
3. 修后实测：悬浮球点「横屏」→ ROTATION_90 生效、无崩溃；再点中心「自动」→ 1x1 方向窗消失、请求释放。

### 踩坑
- 不能用固定 `postDelayed(170)` 等收起动画结束：`animator_duration_scale` 调大后
  160ms 会变成 1.6s，窗口提前缩小 → 画面上会出现一个被右边缘切断的怪球。
  已改成 `setExpanded(false, onEnd = ...)` 用 `AnimatorListenerAdapter.onAnimationEnd` 回调。
- 本机 `adb` 不在 PATH：`C:\android-sdk\platform-tools\adb.exe`；gradlew 需要联网下载发行版，
  改用 `C:\Gradle\gradle-8.14.3\bin\gradle.bat assembleDebug --offline`。
- 自定义开关（`EntryRowView.useSwitch`）的 `checked` 属性在 uiautomator dump 里恒为 false，
  不能据此判断开关状态，只能看悬浮窗是否真的存在。
- `dumpsys window` 的 `mAttrs` 跨行，正则要加 `(?s)`；`Select-String` 管道里带 Context 会报错。
- 测完把 `animator_duration_scale` 还原成 1、`accelerometer_rotation` 还原成 1。

## 悬浮球收起/展开动画重写（用户反馈：收起异常、左右不一致、左侧垂直下落、右侧斜落）

### 定位
旧实现把一次收起拆成三段串行：内容滑到锚点 → 动画结束把窗口从 200dp 缩回 54dp → 再补一次贴边吸附。
锚点 = 球心 −「被推进屏幕后」的盘心，所以收起位移长度 = 盘面为了不出屏被推动的距离
（贴边横向约 69dp；靠上/靠下再叠一段纵向约 69dp）。三段方向不同、又先后执行，
合起来就是一记方向说不清的「掉一下」；左右两侧被推的方向相反，观感更不一致。

### 改法
- `FloatingBallController`：新增 `Frame(x,y,size)`；`restFrame()` / `panelFrameFor()` 是唯一几何来源；
  `animateFrame()` 用一个 `ValueAnimator` 同时推进窗口矩形与 `FloatingBallView.fraction`
  （同一曲线 → 不会窗口先缩/内容后收，也不会内容收完窗口再跳）。
- `collapse()` 落点直接取 `restFrame()`（已含贴边），删掉末尾额外的 `snapToEdge()` 位移；
  拖动松手的吸附走同一个 `animateFrame`。
- 删掉 `FloatingBallView` 的 `anchorX/anchorY` 与 `setExpanded` 内部动画，改为公开 `fraction` / `expanded`
  由控制器驱动；`hitTest` 随 fraction 缩放（窗口在动画中会变尺寸）。
- 选中方向后等收起播完再执行 `onSelect`（`afterCollapse`）；动画被取消也会执行，不会丢方向。
- 顺带：`DisplayManager.DisplayListener` 在屏幕尺寸变化时按 `onLeft`/`yRatio` 复位球。

### 踩坑
- 拖动打断收起时 `snapToEdge` 必须把 fraction 收到 0，否则球尺寸窗口里会留着半个盘。
- `./gradlew` 会去下发行版卡死；用 `C:\Gradle\gradle-8.14.3\bin\gradle.bat ... --offline
  -Dkotlin.compiler.execution.strategy=in-process`（杀掉 java.exe 会把 Kotlin daemon 一起带走）。

### 状态
- `assembleDebug --offline` 通过；未上真机验证（先用静态推理改的，待用户确认观感）。

## 快捷设置磁贴：循环切换 → 弹出五选项悬浮窗

### 需求
磁贴点一下不再按 自动→竖屏→横屏→反向竖屏→反向横屏 循环，而是弹出含 5 个方向选项的悬浮窗。

### 实现（新增 4 个文件 + 改 3 处）
- 新增 `TileMenuActivity`：全屏透明 Activity，自带暗遮罩，点面板外/返回键关闭；选中即落盘 +
  `RotationService.setMode` + `RotationTileService.requestRefresh` 后 finish。
- 新增 `ModeMenuRow`（复用 `RotationGlyphView` / `GlyphPainter` 的图标语言）+ `view_mode_menu_row.xml`：
  图标块 + 名称/朝向 + 勾；选中态 = 主题色淡底 + 1dp 描边 + 图标块填主题色 + 文字转主题色，
  底色用 `RippleDrawable` 自建，选中/未选中都有水波纹。
- 新增 `activity_tile_menu.xml`、`bg_tile_menu_panel.xml`、`anim/tile_menu_in|out.xml`、
  `Theme.ScreenRotator.Popup`（`windowIsTranslucent` + `backgroundDimEnabled=false` + 自定义窗口动画）。
- `RotationTileService.onClick`：先 `updateTile()` 再 `startActivityAndCollapse`；
  **API 34+ 必须用 PendingIntent 版本**（targetSdk 34 起 Intent 版本被后台启动限制拦掉），
  失败时退回原循环切换。`exported=false` 不影响拉起（PendingIntent 以本应用身份执行）。

### 关键决策
- 必须用 Activity：磁贴在 SystemUI 进程，唯一合法带出界面的通道是 `startActivityAndCollapse`；
  用悬浮窗要常驻可接收输入窗口，代价不对等。
- 选中行永远跟 `RotationPrefs`（上次选择）走，**「是否生效」交给顶部说明承担**：
  `已锁定` / `未生效 · 点一下重新锁定`（warn 色）/ 自动态提示。否则进程被杀后弹窗会出现「没有任何选中项」。
- 横屏可用高度 ~393dp，五行带副标题放不下（实测第 5 行被推到折叠线以下）→ `ModeMenuRow.useCompact()`
  收起朝向说明、行高 58→48、图标块 38→34，315dp 内五行全露。

### 真机验证（a766eaed / HyperOS，API 35）
- QS 磁贴点击 → `mCurrentFocus=TileMenuActivity`，面板正确弹出（`exported=false` 无阻）。
- 竖屏面板：标题 + 说明 + 五行；pending 态显示「横屏 未生效 · 点一下重新锁定」并高亮横屏。
- 点「横屏」→ 面板关闭、`mDisplayRotation=ROTATION_90`、prefs=landscape；横屏下再开面板进入紧凑形态，五行全见。
- 点面板外空白 → 面板关闭且 prefs 不变。点「自动」→ prefs=auto，1x1 方向窗消失（悬浮球仍在，故服务按设计常驻）。
- 深色主题（写入 appearance.xml mode=dark）面板底色 `#1B1D23`、文字与高亮对比正常。

### 踩坑
- uiautomator 的 bounds 在横屏下是 2400x1080，竖屏是 1080x2400，两次 dump 不能混用。
- `dumpsys display` 的 `rotation 0` 是物理自然方向，判当前朝向要看 `dumpsys window` 里的
  `mDisplayRotation=` / `winConfig mBounds`（这次差点误判成「没转」）。
- `install -r` 会杀进程 → 悬浮窗消失但 prefs 保留，正好用来复现「未生效」这个分支。

## 选择窗改为贴底抽屉（用户反馈：竖屏放在底部更好按）

### 改动
- `clampPanelWidth()` 的 gravity 由 `TOP` 改 `BOTTOM`，`panelHost` 底部 padding 16dp、顶部只留
  12dp 作安全边（面板贴底后顶部 padding 仅用于「不许顶进状态栏」）。
- 进场/退场动画从中段移到面板自身：`windowAnimationStyle` 只留淡入淡出（`tile_menu_in/out.xml`），
  位移改在 `TileMenuActivity.playEntrance()/playExit()`（32dp 上浮 + alpha 0.2→1，230ms decelerate；
  收起 26dp 下滑 + 淡出 140ms，结束再 finish）。
  **原因：窗口级 translate 会连全屏遮罩一起平移，屏幕上会露出一条没被遮住的亮边。**
- `dismissing` 标志位：退场动画期间不再接受新的点击，避免「连点触发两次切换」。

### 验证（a766eaed）
- 竖屏：面板贴底，五行全见，底部余 24dp；中间帧（`animator_duration_scale=10` 抓拍）遮罩整屏完整、
  面板半透明偏下，无亮边。
- 横屏（紧凑形态）：面板贴底仍然五行全见，顶部余约 55dp。
- 横屏下点「竖屏」→ ROTATION_0 + prefs=portrait + 面板收起；点「自动」→ prefs=auto 且 1x1 方向窗消失。
- 测完已恢复 `animator_duration_scale=1`，设备停在「自动」。

### 改动
- `activity_main.xml`：删掉权限横幅、分区标题、三条快捷入口行、底部说明；只留标题、
  状态胶囊（原来装饰性的 tagline 位置，现在写「跟随系统 / 竖屏 · 已锁定 / 竖屏 · 未生效」）、
  右上角菜单按钮（48dp 触摸区，`ic_more` 三点，缺权限时亮 warn 小圆点）与 5 张卡片。
- 新增 `SettingsSheet`（贴底 Dialog，`Theme.ScreenRotator.Sheet` + `bg_sheet_panel`）：
  权限卡（缺失时才有）、快捷入口三行（复用 `EntryRowView`）、三段式主题选择器、原理说明。
  业务逻辑全部通过 `SettingsSheet.Host` 回落到 MainActivity（原来 private 的
  `notificationsAllowed/canAskNotificationPermission/openOverlaySettings` 改为 override）。
- 新增 `MaxHeightScrollView`（滚动区上限 = 屏幕高 62%）：横屏只有 ~393dp，表头固定 + 内容限高滚动，
  面板不会被顶出屏幕上沿。
- 首启且缺悬浮窗权限时自动弹出菜单（承担原横幅的告知职责）；悬浮球开关改为
  「偏好 ∧ 悬浮窗权限」才算开，与通知栏控制条同一套算法（否则会出现「开着却看不到球」）。

### 实测（a766eaed，1080x2400 / 440dpi）
- 竖屏：面板贴底、上沿 26dp 圆角、底部内容不被手势条压住（`setDecorFitsSystemWindows(false)` + insets padding）。

- 通知权限链路：开关 → 系统原生弹窗 → 允许后副标题变「已常驻通知栏」，toast 正确。
- 主题三段切换 → `recreate()`，深色下遮罩/面板对比正常。
