## Play Console specialUse 前台服务声明

- 应用使用 `FOREGROUND_SERVICE_SPECIAL_USE` 是为了在用户离开应用后仍保持 1×1 全透明、不可触摸的 `TYPE_APPLICATION_OVERLAY` 窗口，其 `LayoutParams.screenOrientation` 承载用户选择的方向请求。
- 声明要点：用户从应用内、通知栏控制条、悬浮球或快捷设置磁贴主动触发；结果是可被用户立即察觉的屏幕旋转；不涉及录屏、截图、输入拦截、无障碍 API 或 WRITE_SETTINGS。
- 不能用绑定 Activity 的服务（离开应用即销毁，方向锁失效）或 WorkManager（可延迟任务，无法持有实时 WindowManager 窗口，也不适合长期瞬时响应）；前台服务 + 常驻通知是受支持且用户可感知、可随时停止的方案。

## 用 adb 录制 Play 演示视频（踩坑记录）

- 成片：`store_assets/video/ScreenRotation-specialUse-demo.mp4`，1080×2400 / 73s / 28MB，一条连续 `screenrecord`，无剪辑。录制对象是 versionCode 2 的 release 包（upload key 签名）。
- 录制脚本：`.workbuddy/tmp/take5.sh` + `uidriver.py`（dump 后按 resource-id / content-desc / 文案点击）。流程：`pm clear` → appops 授予 SYSTEM_ALERT_WINDOW + pm grant 通知 → 菜单里切英文 → 起录 → 点横屏 → 开控制条 → 开计算器 → 通知里点竖屏 → 回应用点 Auto → `settings put system user_rotation` 演示系统接管。
- 关键坑（重录前必看）：
  - `settings put system show_touches 1` 让点击可见，录完设回 0。
  - `screenrecord` 期间旋转不会改变画布尺寸（stsd 只有一条 1080×2400），横屏内容在画布里是躺着的——正常现象，手机上看是正的。
  - MIUI 会把「应用请求过的方向」写回 `user_rotation`，Auto 释放后可能直接停在横屏；演示前必须显式 `accelerometer_rotation 0` + `user_rotation 0` 再点 Auto，否则最后一段会看起来像没释放。
  - `am start -a VIEW -d https://…` 会被解析成「选择活动」弹窗（Chrome/百度），而且百度首页带时政新闻——**绝对不能用浏览器做「其他应用」**。改用系统计算器（`monkey -p com.miui.calculator`）：不联网、无广告、横屏是科学键盘布局。
  - 每轮开始必须 `pm clear`：控制条开关的偏好会跨轮残留，第二轮再点开关等于把它关掉，通知就退化成纯文本（"Controls off"）。
  - 通知栏清空用 `notification_dismiss_view`（desc「清除所有通知。」），不要用右滑——HyperOS 右滑会滑进「更多通知」，那里全是私人消息。
  - 银行类通知会随时插入；录制前清空，录完检查一遍。
- 视频里刻意没有「授予悬浮窗权限」段：HyperOS 的权限页是长应用列表，需要滚五六屏，节奏太差；权限改为 adb 预授予，文档里写清了原因和追问时的回答口径。
