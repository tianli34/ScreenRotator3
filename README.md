# 屏幕旋转（ScreenRotator）

无 Root 的屏幕方向控制工具：前台服务 + 透明悬浮窗，通过 `WindowManager` 的方向仲裁请求屏幕方向。
**仅面向 Android 12（API 31）及以上。**

## 原理

普通无 Root 应用没有能保证覆盖所有应用、所有系统界面的通用强制旋转 API。本工具的做法是：

1. 申请 `SYSTEM_ALERT_WINDOW`（用户在系统设置中开启“显示在其他应用上层”）。
2. 前台服务维护一个 1x1、`TYPE_APPLICATION_OVERLAY` 的悬浮窗口：
   - **窗口级** `alpha = 0`（不是把 View 设为 `INVISIBLE` / `GONE`，后者会让方向请求失效）；
   - `FLAG_NOT_TOUCHABLE` + `FLAG_NOT_FOCUSABLE`，不接收触摸、不抢焦点，不截获输入；
   - 窗口极小且完全透明，满足 Android 12+ 对不可信覆盖层的遮挡触摸拦截规则。
3. 方向请求写在 `WindowManager.LayoutParams.screenOrientation` 上：

   | 目标 | 常量 |
   |---|---|
   | 竖屏 | `SCREEN_ORIENTATION_PORTRAIT` |
   | 横屏 | `SCREEN_ORIENTATION_LANDSCAPE` |
   | 反向竖屏 | `SCREEN_ORIENTATION_REVERSE_PORTRAIT` |
   | 反向横屏 | `SCREEN_ORIENTATION_REVERSE_LANDSCAPE` |

   切换方向时更新同一个窗口的布局参数；切到“自动”时移除窗口，把方向决定权交还系统。
4. 本应用自己的界面（`MainActivity`）**必须跟随锁定状态**：清单里不声明 `screenOrientation`，
   而是由 `syncRequestedOrientation()` 按锁定方向调用 `setRequestedOrientation()`，切到“自动”时
   设为 `SCREEN_ORIENTATION_UNSPECIFIED`。

第 4 步不是可选项。Activity 的方向声明本身就是系统方向仲裁里的一个请求方，与悬浮窗的请求
并列。两者不一致时真机（Redmi / HyperOS）会互相顶：悬浮窗的请求先被采纳、屏幕转过去，界面
随即按自己的方向把显示拉回去；界面每次旋转都会重建、再参与一次仲裁，于是来回翻转，最终停在
「未生效」。清单里写死一个方向会直接压住悬浮窗的请求；写 `fullSensor` 则更隐蔽——它会按传感器
解析出一个具体方向，于是表现为「手机怎么拿，就只有那个朝向能用」。

不涉及屏幕录制、画面变换、触摸坐标变换或输入注入。系统旋转显示时会自行处理输入坐标变换。

## 为什么不用其他方式

- 只关自动旋转 / 改 `USER_ROTATION`：只改变用户旋转偏好，应用的显式方向请求仍可能优先。
- 只设置自己 Activity 的方向：只能锁住本应用自己的界面，离开应用即失效。
- 因此本方案不依赖 `WRITE_SETTINGS`；两个手段并存——悬浮窗管全局，Activity 保证自己的界面不与它冲突。

## 使用

1. 打开应用，按提示授予“显示在其他应用上层”权限（缺权限时菜单会自动弹出，权限行就在最上面）。
2. 在主界面 Bento 卡片里选方向；也可以用下面三个系统级入口，不必回到本应用。
3. 想让「通知栏控制条」常驻，打开右上角菜单 → 「通知栏控制条」把开关打开（见下）。

### 通知栏控制条：应用内一键开启

控制条默认关闭，开关就是唯一入口，走的是一条直白的链路：

1. 用户点开关 → 缺悬浮窗权限则先去系统设置，开关回弹并给出提示；
2. Android 13+ 且还没有通知权限 → 调 `requestPermissions(POST_NOTIFICATIONS)`，
   系统在**当前页面之上**弹出原生小弹窗「是否允许「屏幕旋转」发送通知？」；
3. 点「允许」→ 开关保持打开，`setNotificationBarEnabled(true)` 立刻拉起前台服务，
   通知（含一排五个按钮）当场出现在通知栏；
4. 点「拒绝」→ 开关回弹、提示一句，不留下「开着却没有」的假象；
   再次打开开关时，若系统已判定不再询问，直接跳应用通知设置。

开关的显示条件 = 偏好开启 ∧ 通知能发出去 ∧ 有悬浮窗权限，三者缺一即显示为关，
副标题会说明是被哪一道门挡住了。控制条之外的顺带好处：方向停在「自动」时服务也能
只为控制条常驻，所以不必先锁一个方向。

### 状态的“真话”约定

- `RotationPrefs` 里存的是**上一次选择**，它会跨进程死亡、覆盖安装、重启一直保留；真正锁住方向的只有服务持有的那个悬浮窗。
- 进程被杀（覆盖安装、清后台、重启手机）后悬浮窗消失、屏幕回到系统默认，因此**打开应用时会自动补锁**：若偏好不是「自动」，就用它重新拉起服务。
- 补锁不成功（缺权限、系统不跟随）时，顶部状态显示「横屏 · 未生效」、卡片不点亮；只有悬浮窗确实持有且屏幕朝向一致时才显示「已锁定」。通知栏与快捷磁贴同源，磁贴副标题会标注「（未生效）」。

## 界面与系统入口

主界面只做一件事：**五个方向按钮，外加一个菜单**。
**1 + 2×2** 的 Bento 卡片：顶部整行是「自动」，下方是四个固定方向的 2×2 网格。
每个图标是同一台手机线框的不同转角，**摄像头圆点是方向锚点**（默认用主题色高亮），
所以「横屏 / 反向横屏」不会再靠文字才分得清。选中卡片整卡填充主题色并带同色阴影。
标题下方那枚小胶囊是界面上唯一的「真话」：`跟随系统` / `竖屏 · 已锁定` / `竖屏 · 未生效`。

### 横屏时换一套排布（`layout-land`）

界面自己也会跟着方向转，而横屏可用高度只有 ~390dp：把竖屏那套「整行自动 + 两排网格」
原样搬过去，第二排必然掉到屏幕外，用户得滚动才能点到「横屏 / 反向横屏」——而这一屏恰恰
是用户为了选方向才打开的。所以横屏（含反向横屏）改成了同一套 Bento 语言的横放版本：

```text
+-----------------------------------------------+
| 屏幕旋转  [横屏 · 已锁定]                  ⋮  |
+-------------+----------------+----------------+
|             |    竖屏        |   反向竖屏      |
|    自动     +----------------+----------------+
| （大竖条）  |    横屏        |   反向横屏      |
+-------------+----------------+----------------+
```

- 左侧「自动」是一列 **约 30% 宽的大竖条**（`app:cardTall="true"`）：图标放大到 64dp、
  文案在下方居中、勾选退到右上角，高度与右侧网格一致。
- 右侧四个固定方向是 **约 70% 宽的 2×2 网格**，两行按权重均分剩余高度。
- 一整块内容用 `fillViewport` 撑成屏幕高度、两列都吃满剩余高度，所以**五张卡片一屏全见，
  不需要滚动**（`uiautomator` 里这一屏的 ScrollView 是 `scrollable="false"`）。
- 横屏的标题收小到 22sp、状态胶囊与标题同一行，把纵向空间让给卡片。

### 右上角菜单（SettingsSheet）

除了五个方向按钮，其余功能全部收进右上角这一个入口，贴底弹出：

| 分组 | 内容 |
|---|---|
| 权限（缺失时才有） | 「缺少悬浮窗权限」+ 去授权，替代原来横在主界面顶部的那条横幅 |
| 快捷入口 | 通知栏控制条（开关）、悬浮球（开关）、快捷设置磁贴（添加） |
| 外观 | 三段式选择器：跟随系统 / 浅色 / 深色（选中段整块填充主题色） |
| 语言 | 三段式选择器：跟随系统 / English / 简体中文（语言名用各自的写法展示自己） |
| 关于 | 原理说明（原来堆在页面最底部的那段文字） |

几个刻意的选择：

- **是 Dialog，不是 Activity 也不是 PopupWindow。** 它只服务主界面，不需要跨进程拉起；
  窗口本身就只有面板那么大，面板之外的点击由 WindowManager 判成「窗口外」，直接关闭，
  不必自己铺一层全屏遮罩。窗口只做上下位移 + 淡入，面板始终贴底。
- **菜单按钮会点一个小圆点**：缺悬浮窗权限，或「控制条偏好开着但通知被系统挡住」时亮起，
  按钮的无障碍描述也同步改成「打开菜单，有需要处理的设置」。功能收进菜单不等于藏起来。
- **首次打开、且缺悬浮窗权限时，菜单自动弹出一次。** 否则五张卡片点了都不会有反应，
  用户没有任何线索知道问题在哪 —— 这就是过去那条权限横幅的岗位。
- **横屏可用高度只有 ~393dp**：表头固定在面板顶部，中间那块内容用 `MaxHeightScrollView`
  限高滚动（上限取屏幕高度的 62%），保证面板不会长到把自己顶出屏幕上沿。
- 菜单里的开关状态一律由「偏好 + 权限 + 服务实际持有」共同决定，开关关了副标题就说明
  被哪一道门挡住 —— 不出现「开着却什么都没有」的假象。

### 三个系统级入口

| 入口 | 行为 |
|---|---|
| 通知栏控制条 | 应用内开关（默认关），开启后常驻通知，自定义 RemoteViews 一排五个带锚点图标，点一下即刻切换 |
| 悬浮球 | 边缘半透明小圆点，点开在原地展开罗盘式控制盘：上=竖屏、下=反向竖屏、左=横屏、右=反向横屏、中心=自动；可拖动、松手自动吸附最近边缘 |
| 快捷设置磁贴 | 控制中心添加「屏幕方向」，点按弹出五个方向的悬浮选择窗（见下），磁贴显示当前方向 |

外观默认跟随系统深浅色（夜间底色 `#121212`），在菜单的「外观」里切换 跟随系统 / 浅色 / 深色。
点击卡片有触感反馈，图标会先做 200ms 的小旋转再提交方向。

### 磁贴的方向选择窗

点磁贴不再循环切换，而是弹出一个小面板：五行 = 自动 / 竖屏 / 反向竖屏 / 横屏 / 反向横屏，
每行是「方向图标 + 名称 + 朝向」，选中项整行染主题色淡底、图标块填充主题色、右侧带勾。
点某一行即刻生效并关闭；点面板外任意位置或返回键则取消。磁贴副标题与面板顶部说明同源：

| 顶部说明 | 含义 |
|---|---|
| `竖屏 已锁定 · 点按即刻切换` | 偏好方向与悬浮窗持有一致 |
| `竖屏 未生效 · 点一下重新锁定` | 偏好还在（进程被杀、覆盖安装后常见），但悬浮窗没持有 → 再点一次即可补锁 |
| `点按即刻切换，点空白处关闭` | 当前是「自动」 |

实现要点（`TileMenuActivity` + `ModeMenuRow`）：

- **是 Activity，不是 Dialog 也不是悬浮窗。** 磁贴在 SystemUI 进程里，唯一能把界面带到前台的合法通道是
  `TileService.startActivityAndCollapse`，它只能拉起 Activity。用悬浮窗则要长期占着一个可接收输入的
  覆盖窗口，只为了「点一下换个方向」，代价不对等。
- 该 Activity 全屏透明、自带暗遮罩（`Theme.ScreenRotator.Popup`），`excludeFromRecents` + 独立
  `taskAffinity` + `noHistory`：选完就 finish，不在最近任务里留痕，也不会退到主界面。
- **Android 14+ 必须用 `startActivityAndCollapse(PendingIntent)`**：targetSdk 34 起 Intent 版本会被
  后台启动 Activity 限制拦掉，表现为「点了没反应」。31–33 仍走 Intent 版本。
- 拉起失败（个别 ROM）时退回旧的循环切换，宁可少一层选择，也不让用户点完什么都不发生。
- **面板贴底升起（类底部抽屉）**，左右与底部各留 16dp：控制中心收起后手指就停在下半屏，五行正好落在
  拇指活动范围内；贴顶的卡片会把五个选项全推到最不好够的位置。
- 横屏可用高度只有 ~393dp，此时自动进入紧凑形态（收起朝向说明、行高 58→48dp），保证五行一次全部露出，
  不需要滚动。
- **位移只加在面板上，窗口动画只做淡入**：窗口级 `translate` 会连全屏遮罩一起平移，屏幕上会露出
  一条没被遮住的亮边。收起时面板先滑下去再 `finish`，比直接消失更容易确认「选择已提交」。

## 语言（i18n）

默认语言是英文（`res/values/`），简体中文在 `res/values-zh/`。两边的 key 必须一一对应，
布局与代码里不允许出现硬编码文案。

### 应用内切换

菜单 →「语言」→ 跟随系统 / English / 简体中文。切换后：

- **界面**：`recreate()` 让新实例在 `attachBaseContext` 里重新包一遍 `Configuration`（外观 + 语言一起写）。
- **通知与磁贴**：服务与磁贴不会随 Activity 重建，所以由 `RotationService.onDisplayChanged()` 投递一次
  `ACTION_REFRESH_DISPLAY`，只重建文案（标题、正文、RemoteViews 的无障碍描述、通知通道名称），
  **不重跑 `applyState`** —— 方向锁定与悬浮窗保持原样，屏幕不会闪一下。
- **服务没在跑时**：只更新「已经存在」的通知通道文案，绝不为了刷文案把服务拉起来，也不新建通道。

### 实现要点

- `DisplayContext` 是唯一入口：`wrap(base)` 给 Activity（uiMode + locale），
  `wrapLocale(base)` 给 Service / Tile / Toast（只 locale）。后者故意不碰 uiMode，
  否则通知的 accent 色会跟着应用内主题漂移。
- 返回的 Context **没有主题**，只能取字符串与颜色；布局必须继续用 `Activity.layoutInflater`。
- 服务里所有用户可见文案走 `uiContext`（`DisplayContext.wrapLocale` 的结果），不能用 `this.getString`：
  Service 的 base context 在 attach 时就定死了，切语言不会重建它。
- 通知通道用同 id 重建来更新 name/description（重要性只能降不能升，也不影响用户改过的音效/震动）。
- `RemoteViews` 布局里的 `android:contentDescription` 由宿主进程按**系统语言**解析，
  应用内语言管不到，所以代码里用 `setContentDescription` 显式覆盖。

### 新增一个语种

1. 复制 `res/values-zh/strings.xml` 到 `res/values-xx/strings.xml` 并翻译。
2. `AppLanguage` 加一项枚举（`key` 落盘标识 + `Locale`）。
3. `SettingsSheet.languageSegments()` 与 `dialog_settings_sheet.xml` 的语言段加一段。

## 构建

需要 JDK 17+ 与 Android SDK（compileSdk 36、build-tools 36）。

```bash
./gradlew assembleDebug
```

若 Gradle 分发包下载缓慢，可改用镜像（例如 `https://mirrors.cloud.tencent.com/gradle/gradle-8.9-bin.zip`）
替换 `gradle/wrapper/gradle-wrapper.properties` 中的 `distributionUrl`。

## 已知限制

- 覆盖范围取决于 Android 版本与厂商系统：部分强制方向的应用、锁屏、部分系统界面可能不受影响。
- 本应用界面自己的方向由 `setRequestedOrientation()` 承担，悬浮窗负责其余场景；两者必须同向，
  否则会出现「转一下又弹回来」（原因见「原理」第 4 条）。改这两个地方时不要只改一边。
- 常驻通知的通道重要性是 `IMPORTANCE_DEFAULT`（静音、不震动、不亮灯）。通道重要性只能由 App 下调、
  不能上调，所以改重要性时用的是带版本后缀的通道 id（旧通道会被删除）。
- **「更多通知」收纳：真正的开关是系统里的「不收纳」，不是通道重要性。** Redmi/HyperOS 实测：
  把通道重要性提到 DEFAULT 甚至 HIGH、恢复默认提示音，通知依然被收进「更多通知」——因为 MIUI 是
  按「**自定义通知**（自带 RemoteViews 布局）」这个维度收纳的，不看通道重要性，也不看有没有声音。
  解决办法（一次性设置，持久生效，重装后需重做）：
  **下拉通知栏 → 展开「更多通知」→ 长按本应用通知 → 点「不收纳」→ 确定**
  （确认框文案：「自定义通知不收纳到"更多通知"」）。设置后控制条会直接常驻通知中心主区域。
  应用侧没有对应 API，无法替用户完成这一步。
- Android 13+ 的通知权限只在用户点开「通知栏控制条」开关时申请，系统那次的运行时弹窗最多出现两次；
  之后只能在应用通知设置里改。拒绝时整条通知（含控制条）都不会出现，方向锁定本身不受影响。
- 关掉控制条 ≠ 通知消失：前台服务必须挂一条通知（系统强制）。关掉后通知会退化成一条纯文本，
  不再挂 RemoteViews 与五个方向按钮。只要还锁着方向或开着悬浮球，这条最小通知就一直在。
- 控制条开关与「锁定方向」是两件事：开关只管通知栏里有没有那排按钮，不改变当前锁定状态。
- 「从最近任务划掉即释放」依赖 `onTaskRemoved` 回调：MIUI 等 ROM 划卡会直接杀进程、不回调，
  此时偏好不会被清成「自动」，但屏幕已释放；重新打开应用会按「打开即补锁」的约定恢复上次方向。
- Android 14+ 起应用了 `specialUse` 前台服务类型，上架 Play 需要提交该类型的使用说明。
- 磁贴的选择窗是 Activity：**锁屏状态下系统会拦截后台启动 Activity**，此时磁贴点了不会有窗口，
  服务端会退回「循环切换」这条老路径；解锁后再点即恢复正常。
- Android 12+ 对后台启动前台服务有限制，本工具的方向切换由用户在前台或通知栏主动触发。
- **桌面名称不跟随应用内语言**：`android:label` 由 PackageManager 按系统语言解析，所以在中文系统里
  应用内选 English，图标名仍是「屏幕旋转」；反之英文系统里图标名是 `Screen Rotation`。
- **系统设置里没有本应用的「应用语言」入口**：应用内切换走的是自定义 `Configuration` 覆盖
  （零依赖），没有接 `LocaleManager` / `localeConfig`。这是刻意的取舍，换来 API 31–32 行为一致、
  且通知与磁贴文案能跟着应用内语言走。
- `values-zh` 会被繁体（zh-TW / zh-HK）设备命中而显示简体；将来加 `values-zh-rTW` 即自然分离。
